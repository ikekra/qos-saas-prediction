# performance probe 027: throughput trend

## Objective

Confirm that the QoS platform preserves a reliable **throughput trend** outcome for the affected user flow.

## Preconditions

- A signed-in user has access to a project with at least one configured service.
- Test data is isolated from production records and can be removed after verification.
- The current application build and Supabase configuration are recorded with the evidence.

## Procedure

1. Start from the relevant project or service screen and prepare a representative request.
2. Exercise the throughput trend path with a normal input and a boundary input.
3. Capture the visible result, returned status, and any created metric or audit record.
4. Compare the result with the expected behavior below.

## Expected behavior

The application accepts valid input, rejects unsafe or incomplete input with actionable feedback, and keeps the resulting QoS data consistent across the dashboard, reports, and service detail views.

## Evidence to retain

- Build identifier and environment
- Request or interaction summary
- Observed result and timestamp
- Screenshot or exported report when applicable
