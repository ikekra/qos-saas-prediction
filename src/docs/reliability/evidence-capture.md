# evidence capture reliability runbook

## Purpose

Use this checklist to keep QoS measurements repeatable and actionable for service owners.

## Before the check

- Record the application build, environment, and target service.
- Use representative but non-sensitive request data.
- Confirm the previous measurement window is available for comparison.

## Verification

1. Capture the current latency, availability, and error-rate signals.
2. Compare the result with the agreed threshold and recent trend.
3. Record deviations, the likely owner, and a follow-up date.

## Exit criteria

The check is complete when the evidence is linked to the relevant report and any risk has a clearly assigned next action.
